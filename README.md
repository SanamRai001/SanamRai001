## About

I like the part of software development where an idea becomes a real system: understanding the domain, shaping the data model, designing APIs, handling edge cases, and then building the product experience around a solid core.

My strongest interest is **backend engineering**, but I work across the stack when the product needs it. I am also going deeper into **RAG, retrieval, grounding, evaluation, and AI system architecture** instead of treating an LLM as a black box.

- Backend-first, full-stack capable
- Interested in architecture, APIs, databases, security, and product thinking
- Learning AI by building retrieval and knowledge systems
- I learn fastest by building, breaking things, understanding why, and improving the design

> **Current focus:** building software that stays useful after the demo is over.

## How I think about building

```text
Understand the problem
        ↓
Model the domain and data
        ↓
Define contracts + failure cases
        ↓
Build the backend core
        ↓
Connect the product experience
        ↓
Test → observe → refactor → repeat
```

I care about clear boundaries, useful documentation, honest error handling, and architecture that can grow without turning every new feature into a rewrite.
